The CMS config file (`src/cms.config.ts`) defines custom MDX block components that can be used in the admin panel's content editor.

## Basic Setup

```ts title="src/cms.config.ts"
import { defineComponent } from "astronaut-cms/config";
import { z } from "zod";
import { TriangleAlert } from "lucide-react";

export const components = {
  Alert: defineComponent({
    props: z.object({
      type: z.enum(["info", "warning", "error"]).default("info"),
    }),
    children: "markdown",
    label: "Alert",
    icon: TriangleAlert,
  }),
};
```

## Component Definition

Each component is defined using `defineComponent()` with the following options:

### `props`

- **Type:** `z.ZodType`

A Zod schema defining the component's props.
The admin panel generates a form from this schema.

### `children`

- **Type:** `"markdown" | Record<string, ComponentDefinition>`
- **Default:** `undefined`

Defines what the component accepts as children.
Set to `"markdown"` for components that wrap markdown content.
Set to an object for components that contain named child components (e.g., tabs with tab items).

### `label`

- **Type:** `string`
- **Default:** the component key name

A human-readable label shown in the admin panel.

### `icon`

- **Type:** `LucideIcon`
- **Default:** `undefined`

A [Lucide React](https://lucide.dev) icon shown in the admin panel.

### `wrapper`

- **Type:** `React.ComponentType<{ children: ReactNode }>`
- **Default:** `undefined`

A React component that wraps the component preview in the admin panel.

## Nested Components

Components can contain named child components.
This is useful for container patterns like tabs:

```ts title="src/cms.config.ts"
import { defineComponent } from "astronaut-cms/config";
import { z } from "zod";

export const components = {
  Tabs: defineComponent({
    props: z.object({}),
    children: {
      Tab: defineComponent({
        props: z.object({
          label: z.string(),
        }),
        children: "markdown",
        label: "Tab",
      }),
    },
    label: "Tabs",
  }),
};
```

In MDX content, this renders as:

```mdx
<Tabs>
  <Tab label="First">Content for the first tab.</Tab>
  <Tab label="Second">Content for the second tab.</Tab>
</Tabs>
```

## Asset Fields

A prop that names a media file is declared with the `image()` / `file()` helpers your props
function is handed, the same way a collection schema is handed astro's `image()`. Write `props` as
a function only when you need them; otherwise declare the object directly.

```ts title="src/cms.config.ts"
import { defineComponent } from "astronaut-cms/config";
import { z } from "zod";

export const components = {
  Hero: defineComponent({
    props: ({ image }) =>
      z.object({
        cover: image(),
        caption: z.string().optional(),
      }),
    children: "markdown",
    label: "Hero",
  }),
  Download: defineComponent({
    props: ({ file }) =>
      z.object({
        document: file(),
        label: z.string(),
      }),
    label: "Download",
  }),
  Quote: defineComponent({
    // No asset props, so no helpers are needed.
    props: z.object({ text: z.string(), author: z.string() }),
    label: "Quote",
  }),
};
```

The admin panel renders these as asset pickers connected to the media library. Asset props are
stored as root-absolute path strings and resolved to optimized assets at render time. See
[Asset Handling](/astronaut-cms/guides/asset-handling/) for how the matching component renders them
with `astronaut-cms/Image.astro` or `resolveImage()`/`resolveFile()`.

<Aside type="note">
  There is no importable `image()`. A collection field takes astro's `({ image })` and a component
  prop takes the one its props function is handed, so no spelling can resolve in one place and
  silently fail in the other. `file()` *is* importable, for the one case astro has no helper for: a
  non-image asset in a collection field.
</Aside>

## Matching Astro Components

Each component defined in `cms.config.ts` must have a corresponding Astro component that renders the HTML.
Place these in `src/components/` and import them in your MDX content or configure MDX component mapping.

First, export a bound `ComponentProps` type from your CMS config:

```ts title="src/cms.config.ts" {1} {5}
import { defineComponent, type InferComponentProps } from "astronaut-cms/config";
import { z } from "zod";

export const components = {/* ... */};
export type ComponentProps = InferComponentProps<typeof components>;
```

Then use indexed access in your Astro components:

```astro title="src/components/Alert.astro"
---
import type { ComponentProps } from "@/cms.config";

type Props = ComponentProps["Alert"];

const { type = "info" } = Astro.props;
---

<div class={`alert alert-${type}`}>
  <slot />
</div>
```

The `ComponentProps` utility type extracts the inferred prop types from the CMS config, ensuring type safety between the CMS schema and the rendering component.
