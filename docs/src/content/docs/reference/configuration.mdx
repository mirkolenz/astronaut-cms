## `CmsConfig`

Options passed to the `cms()` integration function in `astro.config.ts`.

```ts
interface CmsConfig {
  config?: string;
  mountPoint?: string;
  storage?: StorageConfig;
  runtime?: "cloudflare" | "node";
  localStorageInDev?: boolean;
  localMediaInDev?: boolean;
  media?: MediaConfig;
  locale?: "en" | "de";
  i18n?: { locales?: string[]; defaultLocale?: string } | false;
  previewUrl?: string;
  ai?: AiConfig;
  webmcp?: WebmcpConfig;
}
```

| Property            | Type                   | Default                 | Description                                                                                                         |
| ------------------- | ---------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `config`            | `string`               | auto-discovered         | Path to the CMS config file relative to the project root                                                            |
| `mountPoint`        | `string`               | `"/admin"`              | URL path for the admin panel                                                                                        |
| `storage`           | `StorageConfig`        | `{ type: "local" }`     | Storage backend configuration                                                                                       |
| `runtime`           | `"cloudflare" \| "node"` | from the adapter      | Where the injected routes read secrets and bindings from                                                            |
| `localStorageInDev` | `boolean`              | `true`                  | Edit the working tree during `astro dev` instead of the configured backend                                          |
| `localMediaInDev`   | `boolean`              | `true`                  | Keep the media library in the working tree during `astro dev` instead of reaching the object store                  |
| `media`             | `MediaConfig`          | `{}`                    | Media library configuration                                                                                         |
| `locale`            | `"en" \| "de"`         | `"en"`                  | Default admin panel UI language                                                                                     |
| `i18n`              | `ContentI18n \| false` | the site's `astro` i18n | Content languages                                                                                                   |
| `previewUrl`        | `string`               | —                       | URL pattern for branch previews from your host                                                                      |
| `ai`                | `AiConfig`             | disabled                | Built-in assistant, see [AI Assistant](/astronaut-cms/guides/ai-agent/)                                             |
| `webmcp`            | `WebmcpConfig`         | disabled                | Expose the CMS tools to agents in the editor's browser, see [Browser Agents](/astronaut-cms/guides/browser-agents/) |

### `runtime`

Where the injected server routes read environment variables and Workers bindings
from, detected from the Astro adapter: `@astrojs/cloudflare` means the Workers
`env` module, anything else means `process.env`.

Set it only for an adapter that deploys to Workers under a name the detection
does not recognise, such as a fork or a wrapper.
Configuring an R2 `binding` without a Cloudflare runtime is a build error rather
than a binding that silently reads as missing.

### `i18n`

Content languages, inherited from the site's own `i18n` in `astro.config.ts`.
Set it to override them, or to `false` to disable multilingual editing.

```ts
{
  locales?: string[];
  defaultLocale?: string;
}
```

See the [Multilingual Content](../../guides/multilingual-content/) guide.

## `StorageConfig`

A discriminated union defining the storage backend.

### Local Storage

```ts
{
  type: "local";
}
```

Reads and writes files on disk via the dev server.
Only available during development.

### GitHub Storage

```ts
{
  type: "github";
  repo: string;
  branch?: string;
  clientId: string;
  publishMode?: "direct" | "pull-request";
}
```

| Property      | Type                         | Default    | Description                                                    |
| ------------- | ---------------------------- | ---------- | -------------------------------------------------------------- |
| `repo`        | `string`                     | required   | Repository in `owner/repo` format                              |
| `branch`      | `string`                     | `"main"`   | Target branch                                                  |
| `clientId`    | `string`                     | required   | GitHub **App** client ID. A classic OAuth App is not supported |
| `publishMode` | `"direct" \| "pull-request"` | `"direct"` | Commit strategy                                                |

The client secret goes in `ASTRONAUT_CMS_GITHUB_CLIENT_SECRET`; see [Storage Backends](/astronaut-cms/guides/storage-backends/#setting-up-the-github-app).

### GitLab Storage

```ts
{
  type: "gitlab";
  project: string;
  branch?: string;
  clientId: string;
  instanceUrl?: string;
  scopes?: string[];
  publishMode?: "direct" | "pull-request";
}
```

| Property      | Type                         | Default                | Description                                     |
| ------------- | ---------------------------- | ---------------------- | ----------------------------------------------- |
| `project`     | `string`                     | required               | Project in `group/project` format               |
| `branch`      | `string`                     | `"main"`               | Target branch                                   |
| `clientId`    | `string`                     | required               | GitLab OAuth application ID                     |
| `instanceUrl` | `string`                     | `"https://gitlab.com"` | GitLab instance URL                             |
| `scopes`      | `string[]`                   | `["api"]`              | OAuth scopes (`api` is required for API writes) |
| `publishMode` | `"direct" \| "pull-request"` | `"direct"`             | Commit strategy                                 |

## `MediaConfig`

Options for the media library.

```ts
interface MediaConfig {
  directory?: string;
  allowedExtensions?: string[];
  maxFileSize?: number;
  alwaysInclude?: string[];
  backend?: MediaBackendConfig;
  optimizeImages?: ImageOptimizationConfig | false;
}
```

| Property            | Type                               | Default            | Description                                                                                                                                              |
| ------------------- | ---------------------------------- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `directory`         | `string`                           | `"src/assets"`     | Media directory relative to project root (`repo` backend)                                                                                                |
| `allowedExtensions` | `string[]`                         | common types       | Allowed file extensions (with leading dot)                                                                                                               |
| `maxFileSize`       | `number`                           | unlimited          | Maximum upload size in bytes. Checked in the admin, signed into the upload URL, and checked again against the stored object before it enters the library |
| `alwaysInclude`     | `string[]`                         | `[]`               | Globs, relative to `directory`, to bundle regardless (`repo` backend)                                                                                    |
| `backend`           | `MediaBackendConfig`               | `{ type: "repo" }` | Where the library's files live                                                                                                                           |
| `optimizeImages`    | `ImageOptimizationConfig \| false` | enabled            | How the browser reshapes an image before uploading it, or `false` to upload originals untouched                                                          |

## `MediaBackendConfig`

A discriminated union defining where media is stored.
It is independent of `storage`: content can live in Git while media lives in an object store.

```ts
type MediaBackendConfig =
  | { type: "repo" }
  | {
      type: "s3";
      bucket: string;
      endpoint: string;
      publicUrl?: string;
      region?: string;
      prefix?: string;
      forcePathStyle?: boolean;
    }
  | {
      type: "r2";
      bucket: string;
      publicUrl?: string;
      accountId?: string;
      binding?: string;
      prefix?: string;
    };
```

| Property         | Backend    | Description                                                                                                                                                     |
| ---------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bucket`         | `s3`, `r2` | Bucket holding the library                                                                                                                                      |
| `endpoint`       | `s3`       | API endpoint, e.g. `https://s3.eu-central-1.amazonaws.com`                                                                                                      |
| `publicUrl`      | `s3`, `r2` | Public base URL the library is served under, and what content resolves against. Omit for a [private library](../../guides/media-library/#no-public-base-at-all) |
| `region`         | `s3`       | Signing region (default `"auto"`)                                                                                                                               |
| `prefix`         | `s3`, `r2` | Key prefix the library is rooted at (default: the bucket root)                                                                                                  |
| `forcePathStyle` | `s3`       | Address objects as `<endpoint>/<bucket>/<key>`                                                                                                                  |
| `accountId`      | `r2`       | Cloudflare account id, for the S3 API endpoint                                                                                                                  |
| `binding`        | `r2`       | Workers R2 binding name, used instead of credentials where available                                                                                            |

See the [Media Library](../../guides/media-library/#where-files-are-stored) guide for the setup an object store needs.

### `alwaysInclude`

A production build bundles only the assets your content references, so a media library full of archive material costs nothing to keep.
Anything referenced from site code rather than from an entry is invisible to that scan and has to be listed here.

```ts title="astro.config.ts"
cms({
  media: {
    alwaysInclude: ["og/**", "brand/logo.svg"],
  },
});
```

Patterns are relative to `directory`, so `"og/**"` means `src/assets/og/**` under the default.
See [Asset Handling](../../guides/asset-handling/#what-a-build-bundles) for how the referenced set is worked out.

## `ImageOptimizationConfig`

How an image is reshaped in the browser before it is uploaded.
See [Media Library](../../guides/media-library/#image-optimization-on-upload) for what it is for and when to turn it off.

```ts
interface ImageOptimizationConfig {
  maxWidth?: number;
  maxHeight?: number;
  maxFileSize?: number;
  format?: "jpeg" | "png" | "webp" | "avif";
  quality?: number;
  minQuality?: number;
}
```

| Property      | Type                                  | Default           | Description                                                                           |
| ------------- | ------------------------------------- | ----------------- | ------------------------------------------------------------------------------------- |
| `maxWidth`    | `number`                              | `2048`            | Widest an upload may be, in pixels. Wider images are scaled down, aspect ratio intact |
| `maxHeight`   | `number`                              | `2048`            | Tallest an upload may be, in pixels                                                   |
| `maxFileSize` | `number`                              | `8388608` (8 MiB) | Size in bytes above which an image is re-encoded even when its dimensions already fit |
| `format`      | `"jpeg" \| "png" \| "webp" \| "avif"` | keep the original | Convert every upload into one format                                                  |
| `quality`     | `number`                              | `0.92`            | Encoder quality for lossy formats, between 0 and 1                                    |
| `minQuality`  | `number`                              | `0.5`             | Lowest quality the `maxFileSize` ladder descends to                                   |

`maxFileSize` is a threshold rather than a guarantee: the image is encoded at `quality`, then at steadily lower ones down to `minQuality`, and the first result that fits is uploaded.
An image that will not compress that far is uploaded at `minQuality` anyway, still smaller than the original.
PNG output ignores the ladder entirely, since a canvas has no lossy PNG encoder.

It is distinct from `maxFileSize` on `MediaConfig`: that one refuses an upload, this one shrinks it first.
