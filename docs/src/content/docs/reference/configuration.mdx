## `CmsConfig`

Options passed to the `cms()` integration function in `astro.config.ts`.

```ts
interface CmsConfig {
  config?: string;
  mountPoint?: string;
  storage?: StorageConfig;
  localStorageInDev?: boolean;
  localMediaInDev?: boolean;
  media?: MediaConfig;
  locale?: "en" | "de";
  i18n?: { locales?: string[]; defaultLocale?: string } | false;
}
```

| Property     | Type                   | Default                 | Description                                              |
| ------------ | ---------------------- | ----------------------- | -------------------------------------------------------- |
| `config`     | `string`               | auto-discovered         | Path to the CMS config file relative to the project root |
| `mountPoint` | `string`               | `"/admin"`              | URL path for the admin panel                             |
| `storage`    | `StorageConfig`        | `{ type: "local" }`     | Storage backend configuration                            |
| `localStorageInDev` | `boolean`       | `true`                  | Edit the working tree during `astro dev` instead of the configured backend |
| `localMediaInDev`   | `boolean`       | `true`                  | Keep the media library in the working tree during `astro dev` instead of reaching the object store |
| `media`      | `MediaConfig`          | `{}`                    | Media library configuration                              |
| `locale`     | `"en" \| "de"`         | `"en"`                  | Default admin panel UI language                          |
| `i18n`       | `ContentI18n \| false` | the site's `astro` i18n | Content languages                                        |

### `i18n`

Content languages, inherited from the site's own `i18n` in `astro.config.ts`.
Set it to override them, or to `false` to disable multilingual editing.

```ts
{
  locales?: string[];
  defaultLocale?: string;
}
```

See the [Multilingual Content](../../guides/multilingual-content/) guide.

## `StorageConfig`

A discriminated union defining the storage backend.

### Local Storage

```ts
{
  type: "local";
}
```

Reads and writes files on disk via the dev server.
Only available during development.

### GitHub Storage

```ts
{
  type: "github";
  repo: string;
  branch?: string;
  clientId: string;
  authMode?: "oauth-app" | "github-app";
  flow?: "device" | "redirect";
  scopes?: string[];
  publishMode?: "direct" | "pull-request";
}
```

| Property      | Type                          | Default       | Description                                                                      |
| ------------- | ----------------------------- | ------------- | -------------------------------------------------------------------------------- |
| `repo`        | `string`                      | required      | Repository in `owner/repo` format                                                |
| `branch`      | `string`                      | `"main"`      | Target branch                                                                    |
| `clientId`    | `string`                      | required      | GitHub OAuth App or GitHub App client ID                                         |
| `authMode`    | `"oauth-app" \| "github-app"` | `"github-app"` | Authentication strategy. `github-app` issues repository-limited, expiring tokens; `oauth-app` issues a coarse, non-expiring `repo` token. See [Security Model](/astronaut-cms/guides/security/#the-browser-token) |
| `flow`        | `"device" \| "redirect"`      | `"device"`    | Sign-in flow; `redirect` needs a client secret and an SSR adapter                |
| `scopes`      | `string[]`                    | `["repo"]`    | OAuth scopes for `oauth-app` mode; ignored for `github-app`                      |
| `publishMode` | `"direct" \| "pull-request"`  | `"direct"`    | Commit strategy                                                                  |

### GitLab Storage

```ts
{
  type: "gitlab";
  project: string;
  branch?: string;
  clientId: string;
  instanceUrl?: string;
  scopes?: string[];
  publishMode?: "direct" | "pull-request";
}
```

| Property      | Type                         | Default                | Description                                     |
| ------------- | ---------------------------- | ---------------------- | ----------------------------------------------- |
| `project`     | `string`                     | required               | Project in `group/project` format               |
| `branch`      | `string`                     | `"main"`               | Target branch                                   |
| `clientId`    | `string`                     | required               | GitLab OAuth application ID                     |
| `instanceUrl` | `string`                     | `"https://gitlab.com"` | GitLab instance URL                             |
| `scopes`      | `string[]`                   | `["api"]`              | OAuth scopes (`api` is required for API writes) |
| `publishMode` | `"direct" \| "pull-request"` | `"direct"`             | Commit strategy                                 |

## `MediaConfig`

Options for the media library.

```ts
interface MediaConfig {
  directory?: string;
  allowedExtensions?: string[];
  maxFileSize?: number;
  alwaysInclude?: string[];
  backend?: MediaBackendConfig;
}
```

| Property            | Type                 | Default            | Description                                          |
| ------------------- | -------------------- | ------------------ | ---------------------------------------------------- |
| `directory`         | `string`             | `"src/assets"`     | Media directory relative to project root (`repo` backend) |
| `allowedExtensions` | `string[]`           | common types       | Allowed file extensions (with leading dot)           |
| `maxFileSize`       | `number`             | unlimited          | Maximum upload size in bytes. Checked in the admin, and signed into the presigned upload so the store enforces it too |
| `alwaysInclude`     | `string[]`           | `[]`               | Globs, relative to `directory`, to bundle regardless (`repo` backend) |
| `backend`           | `MediaBackendConfig` | `{ type: "repo" }` | Where the library's files live                       |

## `MediaBackendConfig`

A discriminated union defining where media is stored.
It is independent of `storage`: content can live in Git while media lives in an object store.

```ts
type MediaBackendConfig =
  | { type: "repo" }
  | {
      type: "s3";
      bucket: string;
      endpoint: string;
      publicUrl: string;
      region?: string;
      prefix?: string;
      forcePathStyle?: boolean;
    }
  | {
      type: "r2";
      bucket: string;
      publicUrl: string;
      accountId?: string;
      binding?: string;
      prefix?: string;
    };
```

| Property         | Backend    | Description                                                                 |
| ---------------- | ---------- | --------------------------------------------------------------------------- |
| `bucket`         | `s3`, `r2` | Bucket holding the library                                                   |
| `endpoint`       | `s3`       | API endpoint, e.g. `https://s3.eu-central-1.amazonaws.com`                    |
| `publicUrl`      | `s3`, `r2` | Public base URL the library is served under, and what content resolves against |
| `region`         | `s3`       | Signing region (default `"auto"`)                                            |
| `prefix`         | `s3`, `r2` | Key prefix the library is rooted at (default: the bucket root)                |
| `forcePathStyle` | `s3`       | Address objects as `<endpoint>/<bucket>/<key>`                               |
| `accountId`      | `r2`       | Cloudflare account id, for the S3 API endpoint                               |
| `binding`        | `r2`       | Workers R2 binding name, used instead of credentials where available         |

See the [Media Library](../../guides/media-library/#where-files-are-stored) guide for the setup an object store needs.

### `alwaysInclude`

A production build bundles only the assets your content references, so a media library full of archive material costs nothing to keep.
Anything referenced from site code rather than from an entry is invisible to that scan and has to be listed here.

```ts title="astro.config.ts"
cms({
  media: {
    alwaysInclude: ["og/**", "brand/logo.svg"],
  },
});
```

Patterns are relative to `directory`, so `"og/**"` means `src/assets/og/**` under the default.
See [Asset Handling](../../guides/asset-handling/#what-a-build-bundles) for how the referenced set is worked out.
